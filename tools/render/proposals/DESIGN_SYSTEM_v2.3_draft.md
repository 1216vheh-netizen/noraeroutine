## 0. 상위 규칙과 승인 절차

이 문서는 `CLAUDE.md`를 따릅니다. 서로 충돌하면 **CLAUDE.md가 우선**합니다.

**작업 절차 (CLAUDE.md 7항, 단계 생략 금지)**
1. 아침회의
2. 콘텐츠 기획
3. 시안 제작
4. 사용자 검수
5. 승인
6. 게시 준비. 실제 게시는 별도 승인이 필요합니다.

**사용자 승인 없이 하지 않는 일 (CLAUDE.md 8항)**

- 외부 서비스 설정 변경

**이 문서에서 추가로 승인을 받는 일**

- 이 문서를 개정하는 일

**승인의 범위**
- 승인은 해당 작업 한 건에만 유효합니다. 다른 작업으로 넓혀 해석하지 않습니다.

## 1. 브랜드 정체성과 디자인 철학

**한 문장 정의**
> 노래루틴은 **같이 연습하고 같이 실수하며 성장하는, 우리 동네 연습실 친구들**입니다.

**디자인 원칙 다섯 가지**
1. **진짜 연습하는 하루**: 평범한 연습실, 생활감 있는 소품, 꾸미지 않은 모습을 보여 줍니다.
2. **한 장, 한 메시지**: 정보를 많이 담는 것보다 한 번에 이해되는 것을 우선합니다.
3. **모바일 우선**: 모든 판단은 휴대폰에서 한 손으로 스크롤하는 상황을 기준으로 합니다.
4. **편안한 친근함**: 귀엽고 따뜻하게 만들되, 글씨는 언제나 잘 읽히게 합니다.
5. **일관된 사람**: 고정 캐릭터의 얼굴과 의상은 공식 원본이 등록되면 그 원본 그대로 유지하며, 절대 임의로 바꾸지 않습니다(12장).

**말투**
- 함께 연습하는 친구처럼 씁니다. 존댓말을 기본으로 하되 편하게 씁니다.
- 실수를 숨기지 않습니다. 예: "저도 여기서 음이탈 났어요"
- 피하는 표현: "무조건", "1주 만에 완성", "100% 성공" 같은 과장

**사용하지 않는 것**
- 고급 광고·화보 같은 연출, 영화 같은 조명, 과한 피부 보정
- 보라색 그라데이션, 네온, 글래스 효과, 진한 그림자
- 같은 모양의 카드를 격자로 반복하는 AI 템플릿식 구성
- 실존 가수의 사진이나 초상

보컬 교육, 성장 스토리, AI 음악 기술 등 일반 콘텐츠 전체에 씁니다.

## 5. 인스타그램 카드뉴스 (1080×1350px, 4:5)

**기본 틀**
| 요소 | 규칙 |
|---|---|
| 바깥 여백 | 좌우 80px, 위아래 96px |
| 콘텐츠 영역 | **가로 920px × 세로 1158px** (1080 − 80×2, 1350 − 96×2) |
| 격자 미리보기 | 프로필 격자가 3:4로 보이면 좌우가 약 34px씩 잘립니다. 80px 여백 안쪽이므로 콘텐츠 영역은 안전합니다 [확인 필요: 최신 격자 비율] |
| 브랜드 표시 | 왼쪽 위 마이크 아이콘 + `노래루틴` |
| 쪽 번호 | 오른쪽 위 알약형 `4 / 6` |
| 계정 표시 | 왼쪽 아래 `@noraeroutine` |
| 페이지 수 | 6~8페이지 |
| 원칙 | **한 장에 핵심 메시지 하나** |

- 브랜드 표시, 쪽 번호, 계정 표시도 콘텐츠 영역 안에 둡니다.
- 같은 규격을 블로그 본문 기본 이미지로 재사용합니다(7장 7-2).

**화면 유형 5가지 (번갈아 사용)**
| 유형 | 구성 | 사용 위치 |
|---|---|---|
| C1 표지 | 크림 배경 + 큰 제목 + 둥근 액자형 캐릭터 사진 | 첫 페이지 |
| C2 한 문장 | 크림 배경에 큰 문장 하나. 핵심 단어에 연핑크 형광펜 밑줄 | 문제 제기, 핵심 정리 |
| C3 단계 | STEP 배지 + 제목 + 사진 + 설명 박스 | 연습 방법 |
| C4 비교 | ✕ / ○ 박스로 잘못된 예와 올바른 예 비교. ○ 박스는 로즈 테두리로 강조 | 비교 |
| C5 마무리 | 요약 + 연핑크 말풍선 안의 질문형 마무리 + 저장·공유 안내 | 마지막 페이지 |

- 같은 유형을 3페이지 이상 연속으로 쓰지 않는 것을 권장합니다.
- **캐릭터 공식 원본이 등록되기 전**에는 캐릭터 사진을 쓰지 않고 C2 구성을 씁니다(12장).

**장식 권장 기준 (절대 제한이 아니라 권장)**
| 요소 | 권장 기준 |
|---|---|
| 둥근 박스·카드 | 모서리 24px. 한 장에 3개 안팎 |
| STEP 배지·말풍선·댓글 유도 요소 | 연핑크 바탕 + 로즈 또는 차콜 글자 |
| 형광펜 밑줄 | 한 장에 1곳 안팎 |
| 낙서형 아이콘 (음표, 말풍선, 반짝임) | 한 장에 2개 안팎 |
| 손글씨풍 짧은 메모 | 한 장에 1개 안팎. 정보 전달용으로는 쓰지 않음 |
| 이모지 | 문장 끝에 가볍게 |
| 장식 원 | 화면 모서리에 1~2개, 아주 연한 분홍 |
| 그림자 | 아주 옅게만 |

**권장 기준을 넘어도 반드시 지킬 것**
- 장식이 글자나 얼굴을 가리지 않을 것
- 8장의 대비 기준과 최소 글자 크기를 지킬 것

**사진 위 글자 처리**
- 사진 밖에 배치하는 것을 기본으로 합니다.
- 사진 위에 올려야 하면 크림 단색 띠를 깔고 올립니다. 그라데이션 띠는 쓰지 않습니다.

## 8. 모바일 가독성과 접근성 기준

1. 글자 대비는 본문 **4.5:1 이상**, 큰 제목(약 72px 이상) **3:1 이상**으로 합니다. 웹 접근성 기준(WCAG AA)입니다.
2. 1080px 화면 기준 본문 최소 36px, 캡션 최소 32px입니다. 휴대폰 폭 390px에서 캡션이 약 11.6px로 보이는 크기입니다(28px은 약 10.1px).
3. 정보를 색으로만 전달하지 않습니다. ✕/○ 기호나 글자로도 구분합니다. 연핑크 면(배경 대비 1.12:1)만으로 의미를 구분하지 않습니다.
4. 강조 테두리 같은 의미 있는 선과 아이콘은 배경 대비 3:1 이상으로 합니다(로즈 테두리 5.10:1).
5. 장식은 권장 기준을 넘더라도 글자와 얼굴을 가리면 안 됩니다.
6. 휴대폰 실제 크기에서 2초 안에 핵심 문장이 읽히는지 확인합니다. 블로그 썸네일은 목록 크기로 확인합니다.
7. 영어·음악 용어는 한글을 함께 씁니다. 예: 두성(Head Voice), E5(3옥타브 미)
8. 웹사이트에는 대체 텍스트, 키보드 조작, 최소 터치 영역 44×44px을 적용합니다.

## 9. Canva 마스터 템플릿 운영 원칙

1. **고정 요소는 마스터에서만 바꿉니다.** 폰트 종류, 배경색, 여백, 브랜드 표시 위치가 해당합니다.

3. **검수는 읽기만 합니다.** 수정은 사용자 승인 후에만 합니다.

## 10. AI 생성물 표시

AI 생성물 표시는 **두 가지를 따로** 관리합니다. 하나가 다른 하나를 대신하지 않습니다.

| 구분 | ① 이미지 안의 표시 | ② 플랫폼 AI 라벨 설정 |
|---|---|---|
| 무엇 | 디자인 안에 넣는 문구 (예: "AI 연출 이미지") | 업로드할 때 플랫폼에서 켜는 AI 생성 정보 표시 |
| 성격 | 노래루틴 자체 기준 | 플랫폼 정책에 따른 설정 |
| 적용 대상 | AI로 만든 인물이 들어간 모든 이미지·영상 | 플랫폼 정책이 요구하는 경우 [확인 필요: 인스타그램·네이버 각 정책] |
| 담당 단계 | 시안 제작 (디자인에 포함) | 게시 준비 단계에서 확인. 실제 설정과 게시는 사용자 승인 후 |
| 검수 | 14장 E 항목 | 14장 E 항목 |

**① 이미지 안의 표시 (임시 기준, 정책 확인 후 확정)**
- 위치: 사진 오른쪽 아래, 사진 안쪽 여백 16px
- 크기: 32px, 흰 글자
- 배경: 차콜(`#2B2523`) 알약형, **불투명도 75% 이상**
  - 계산 근거: 사진이 흰색인 최악의 경우에도 불투명도 70%에서 5.65:1, 80%에서 7.85:1이 나옵니다.
- 최종 문구와 위치는 플랫폼 정책을 확인한 뒤 정합니다. [확인 필요]

**② 플랫폼 AI 라벨 설정**
- 각 플랫폼에서 AI 생성물 라벨 설정이 필요한지, 필요하면 어떤 조건인지 게시 전에 확인합니다. [확인 필요]
- 확인 결과는 게시 준비 체크리스트에 기록합니다.

- 두 캐릭터가 함께 배우고, 실수하고, 웃고, 다시 시도하는 모습을 보여 줍니다.
- 실수와 NG 장면은 성장 스토리의 핵심이므로 숨기지 않습니다.
- 화면 자막은 짧게 쓰고, 카드뉴스와 같은 폰트와 색을 씁니다.

**AI 자연스러움 검수**
| 구분 | 확인 항목 |
|---|---|
| 얼굴 | 눈 깜빡임이 자연스럽다. 시선이 엉뚱한 곳을 향하지 않는다. 표정이 갑자기 바뀌지 않는다 |
| 입 | 노래할 때 입 벌림이 음 높이와 발음에 맞다. 치아와 입술이 장면 내내 같다 |
| 몸 | 호흡할 때 어깨와 가슴이 자연스럽게 움직인다. 손가락 개수와 모양이 정상이다. 마이크와의 거리가 갑자기 바뀌지 않는다 |
| 소리 | 음성과 입 모양이 어긋나 보이지 않는다 [확인 필요: 적용 기준] |
| 동작 | 실제 보컬 연습에서 가능한 동작이다. 목에 힘을 주는 모습 등을 과장하지 않는다 |
| 공통 | 하나라도 부자연스러우면 그 장면은 다시 제작합니다. 얼굴과 의상 고정 원칙(12장)은 그대로 적용합니다 |

## 12. 고정 캐릭터 운영 규칙 (디자인 측면)

**최우선 원칙**
1. 공식 원본이 등록되면, 그 원본의 얼굴, 헤어스타일, 의상, 전체 외형을 **절대 임의로 바꾸지 않습니다.**
2. **공식 원본이 등록되기 전에는 캐릭터 이미지를 생성하거나 재생성하지 않습니다.** 비슷하게 만든 대체 이미지도 만들지 않습니다.
3. **원본 후보는 공식 원본이 아닙니다.** 후보 이미지는 검토용 참고 자료일 뿐이며, 콘텐츠 제작이나 검수 통과의 기준으로 쓰지 않습니다.

**외형 기준 문서 (독립 관리)**
- 캐릭터 외형의 상세 기준은 이 문서가 아니라 **캐릭터별 `metadata.md`**에서 관리합니다. 이 파일은 공식 원본을 등록할 때 함께 만듭니다.
- 등록 전까지 외형 기준은 CLAUDE.md 4항의 캐릭터 표(글로 된 정의)뿐입니다.
- 디자인 문서를 바꿔도 캐릭터 기준은 바뀌지 않습니다.

**현재 상태: 두 캐릭터 모두 공식 원본 미등록**
| 캐릭터 | 등록 상태 | 원본 후보·참고 자료 | 등록 전 남은 조건 |
|---|---|---|---|
| 여성 | ❌ **공식 원본 미등록** | 원본 후보: 공식 참고 이미지 ④ (여성 단독 녹음실 사진). **최종 승인본 아님** | 워터마크 없는 원본 확보, 상업적 이용 조건 확인, 대표 최종 승인, 등록 승인 |
| 남성 | ❌ **공식 원본 미등록** | 얼굴 참고 자료: 캐릭터 설정 보드 ①. 단독 원본 후보 **없음** | 단독 고해상도 원본 확보, 상업적 이용 조건 확인, 대표 최종 승인, 등록 승인 |

- 남성 고정 의상은 **회색 후드 + 흰색 크루넥 티셔츠**로 제안된 상태입니다. 공식 원본 등록 시 확정합니다.

**레퍼런스 경로 (파일은 미등록)**
```
assets/characters/
├── female/
│   ├── v1_reference.{원본 확장자}   # 공식 대표 원본 = 받은 원본 파일 그대로
│   ├── metadata.md                  # 외형 기준, 출처, 권리, 체크섬, 변경 이력
│   ├── reference/                   # 각도·표정·입 모양 승인본 (원본 그대로)
│   └── work/                        # 작업용 사본 (필요할 때만, 공식 원본 아님)
└── male/
    └── (female과 같은 구성)
```
- 위 폴더와 파일은 **공식 원본 등록이 승인될 때** 만듭니다. 지금은 존재하지 않습니다.
- 외형 자체가 바뀌는 경우는 사용자 승인을 받아 `v2_`로 새로 등록합니다.

**공식 원본 보존**
- 받은 원본은 **확장자와 파일 내용을 그대로** 보존합니다. 예: JPEG로 받으면 `v1_reference.jpg`
- 다시 저장, 압축, 크기 조절, 형식 변환, 메타데이터 제거를 하지 않습니다. 받은 파일의 체크섬과 등록된 파일의 체크섬이 같아야 합니다.
- 공식 원본은 삭제하거나 덮어쓰지 않습니다.

**작업용 사본 (필요한 경우에만)**
| 항목 | 규칙 |
|---|---|
| 만드는 조건 | 제작 도구가 원본과 다른 형식(예: PNG)을 요구할 때만 만듭니다. 만들 때마다 사용자 승인을 받습니다 |
| 위치 | `assets/characters/{female,male}/work/` |
| 파일명 | `{원본 파일명}__work.{사본 확장자}` (밑줄 두 개). 예: `v1_reference__work.png` |
| 체크섬 | 사본도 자기 체크섬을 따로 기록합니다. 원본 파일명과 원본 체크섬, 변환 도구와 설정, 만든 날짜, 승인 내용을 함께 적습니다 |
| 지위 | **공식 원본을 대체할 수 없습니다.** 얼굴 비교 검수의 기준으로 쓰지 않고, 항상 공식 원본과 비교합니다 |
| 정리 | 필요 없어진 사본은 승인 후 삭제할 수 있습니다. 공식 원본은 삭제하지 않습니다 |

**파일명 규칙**
| 규칙 | 내용 |
|---|---|
| 형식 | `v{버전}_{분류}_{세부}.{원본 확장자}` |
| 대표 원본 | `v{버전}_reference.{원본 확장자}` |
| 작업용 사본 | `{원본 파일명}__work.{사본 확장자}`. `work/` 폴더에만 둡니다 |
| 분류 | `angle`(각도) · `expr`(표정) · `mouth`(입 모양) · `outfit`(의상) · `scene`(장면) |
| 예시 | `v1_angle_front.jpg`, `v1_angle_three-quarter-left.png`, `v1_expr_smile.jpg`, `v1_mouth_a.png`, `v1_outfit_upper-body.jpg` |
| 표기 | 영어 소문자와 숫자만. 분류 구분은 `_`, 단어 연결은 `-`. 한글과 띄어쓰기 금지 |
| 덮어쓰기 금지 | 등록된 파일은 절대 덮어쓰지 않습니다. 고쳐야 하면 새 파일로 등록하고 이전 파일은 보존합니다 |
| 버전 | 외형 자체가 바뀔 때만 올립니다. 각도·표정을 추가할 때는 버전을 올리지 않습니다 |

**SHA-256 체크섬 관리**
- 등록할 때 파일마다 SHA-256 체크섬을 `metadata.md`에 기록합니다. 승인일과 승인자도 파일 단위로 기록합니다.
- 공식 원본과 작업용 사본은 **별도 표**에 기록해 섞이지 않게 합니다. 작업용 사본 기록에는 어느 원본에서 만들었는지(원본 파일명과 체크섬)를 함께 적습니다.
- 확인 시점: 캐릭터가 들어가는 콘텐츠를 제작하기 전, 월 1회 정기 점검, 캐릭터 폴더가 바뀌는 커밋 전
- 기록과 다르면: 그 파일의 사용을 멈추고 보고합니다. 원인을 확인한 뒤 Git 이력에서 등록 당시 파일을 복구합니다.
- 체크섬은 **파일이 바뀌지 않았다는 것만** 보증합니다. 콘텐츠의 얼굴이 원본과 같은지는 아래 검수로 따로 판단합니다.

**metadata.md 고정 외형 항목**
- 얼굴형·얼굴 비율, 눈·코·입의 형태와 위치, 헤어라인·머리 모양·머리색, 피부색·기본 인상, 승인 의상, 나이대, **체형**(키 인상, 어깨너비, 체격)

**영상 클립 (`clips/`)**
- 위치: `assets/characters/{female,male}/clips/`
- 파일명: `v{버전}_clip_{용도}_{번호}.{원본 확장자}` (예: `v1_clip_sing-u-scale_001.mp4`)
- 승인된 클립만 둡니다. 클립도 공식 원본처럼 확장자·내용을 바꾸지 않고, SHA-256을 `metadata.md`의 클립 표에 기록합니다.
- 클립마다 기록할 것: 장면 용도, 길이, 생성 도구·모델, **사용한 공식 원본 버전**, **사용한 음성 파일의 SHA-256**, 원본 대조 검수 결과, 승인자
- 립싱크 클립은 서비스가 다시 인코딩한 소리를 쓰지 않습니다. 소리는 마스터 음성 파일을 씁니다.
- 클립의 얼굴도 공식 원본과 나란히 비교 검수하며, 다르면 폐기합니다(위 검수 규칙과 같음).

**얼굴 위치 파일 (`.face.json`)**
- 클립과 같은 이름으로 둡니다. 예: `v1_clip_sing-u-scale_001.face.json`
- 필수 항목: 클립 파일명, 클립 SHA-256, 프레임 속도, 크기, 화면 배치(위치·배율), 얼굴 상자 키프레임(0.5초 간격 이하), 표시한 사람·도구, 확인한 사람
- 얼굴 상자는 이마~턱, 양 볼 끝을 감쌉니다. 지금은 사람이 직접 표시하고 다른 사람이 확인합니다. 자동 얼굴 찾기 도구는 별도 검토 후 사용합니다 [확인 필요]

**목소리 연결**
- 캐릭터 `metadata.md`에는 목소리 ID만 적습니다(예: `voice: ai-female-v1`). 목소리 정보는 `assets/voices/{목소리 ID}/metadata.md`에서 관리합니다.

**디자인에서 지킬 것**
- 얼굴 위에 글자, 로고, 스티커, 장식을 올리지 않습니다.
- 색을 바꾸는 필터나 과한 보정을 쓰지 않습니다.
- 인물의 가로세로 비율을 바꾸지 않습니다.
- 사진 액자의 모서리를 둥글게 하는 것은 괜찮습니다. 얼굴이 잘리지 않게 합니다.

**검수**
- 시안마다 **등록된 공식 원본**과 나란히 비교합니다.
- 고정 항목이 하나라도 다르면 그 시안은 **폐기하고 다시 만듭니다.**

## 14. 디자인 품질 검수 체크리스트 (게시 전)

각 항목은 ✅ 통과 / ❌ 위반 / ❓ 확인 불가로 표시합니다. 위반은 **큰 위반**(색·캐릭터·가독성·저작권)과 **작은 위반**(여백·장식 권장 기준 등)으로 나눕니다.

**A. 브랜드 일치 (Canva 공식 브랜드 검수 기준)**
- [ ] 색상: 2장·3장에 지정된 색만 썼다. 벗어난 색이 있으면 가장 가까운 브랜드 색을 함께 적는다.
- [ ] 테마: 일반 콘텐츠는 스튜디오 웜, 고음 챌린지는 나이트 세션 라벨을 썼다.
- [ ] 글꼴: 4장의 Pretendard 기준을 지켰다. 포인트 폰트는 승인된 것만 썼다.
- [ ] 말투: 함께 연습하는 친구 말투이고 과장 표현이 없다.
- [ ] 일관성: 모든 장에 같은 여백, 브랜드 표시, 쪽 번호 규칙이 적용됐다.

**B. 디자인 품질 (Canva 공식 디자인 피드백 기준, 높음/중간/낮음으로 보고)**
- [ ] 시선 순서: 가장 중요한 문장이 가장 먼저 보인다.
- [ ] 문구: 한 장에 핵심 메시지가 하나뿐이고 오탈자가 없다.
- [ ] 여백: 카드뉴스와 블로그 본문 이미지는 콘텐츠 영역 920×1158px 안, 릴스는 글자 배치 폭 860px 안, 스토리는 콘텐츠 영역 920×1330px 안, 썸네일은 중앙 760×760px 안에 들어간다.
- [ ] 스토리: 스티커를 쓸 경우 스티커 공간(920×480px)을 비워 두었다.
- [ ] 가독성: 휴대폰 실제 크기에서 2초 안에 읽힌다.
- [ ] 접근성: 8장의 대비 기준을 지켰고 색에만 의존하지 않는다.
- [ ] 플랫폼 적합성: 크기가 맞고 금지 구역을 지켰다.
- [ ] 장식: 권장 기준 안이거나, 넘었더라도 글자와 얼굴을 가리지 않는다.
- [ ] 반복 회피: AI 템플릿처럼 같은 카드가 반복되지 않는다.

**C. 일상감**
- [ ] 평범한 연습 공간으로 보인다 (화려한 장비, 네온, 영화 조명이 없다)
