# 노래루틴 릴스 검증 11~20번 구현 계획 (설계안)

- 기존 1~10번(`lib/validate.py`)은 그대로 유지한다. 신규 항목은 별도 파일 `lib/validate_media.py`로 만들어, 실제 음성·클립이 들어간 결과물에만 적용한다 (신호음 렌더링에는 해당 없음 → "건너뜀"으로 표시).
- 구분: **자동** = 프로그램이 통과/실패 판정 / **자동+사람** = 프로그램이 측정·후보 표시, 최종 판정은 사람 / **사람** = 사람 검수 기록이 있어야 통과.
- 기준값 중 **[기준 확인 필요]** 는 실제 녹음으로 시험한 뒤 대표 승인으로 확정한다.

| 번호 | 검사 | 구분 | 구현 방법 (무료·로컬 도구만) | 통과 기준 (초안) |
|---|---|---|---|---|
| 11 | 전체 음량·최고 레벨 | 자동 | ffmpeg `ebur128=peak=true` 로 통합 음량(LUFS)·True Peak 측정 | 약 −14 LUFS ±1, True Peak ≤ −1 dBTP [기준 확인 필요] |
| 12 | 소리 찢어짐(클리핑) | 자동 | ffmpeg `astats` 의 최대값·클리핑 샘플 수 | 클리핑 샘플 0 |
| 13 | 음성–자막 싱크 | 자동 | 음성 조각별 소리 시작점(에너지 상승) 검출 → spec의 `voice.in`, 자막 `data-in`과 비교 | 차이 ±2프레임(약 67ms) 이내 [기준 확인 필요] |
| 14 | 음성이 장면 안에 들어감 | 자동 | 조각별 길이 측정 → 장면 시작·끝(전환 0.15초 제외)과 비교 | 장면 밖으로 넘친 음성 0건 |
| 15 | 배경음악 덕킹 | 자동 | 음성 구간과 비음성 구간의 BGM 음량 차이(트랙 분리 상태에서 측정) | 음성 구간에서 BGM이 −10 dB 이상 낮음 [기준 확인 필요] |
| 16 | 시범 음정·타이밍 | 자동+사람 | numpy 자기상관으로 음정 추출 → 음 계단 점(`ladder`) 시간·음 높이와 비교. "삐끗" 구간은 의도된 이탈로 표시 | 점 표시와 음 시작 ±1프레임. 음정 판정은 **선생님 확인 필수** |
| 17 | 이상한 무음·끊김 | 자동 | ffmpeg `silencedetect` | 장면 중간 0.8초 이상 무음 0건 (의도된 쉼은 spec에 표시) [기준 확인 필요] |
| 18 | 립싱크 자연스러움 | 사람 | 검수용 0.5배속 영상·입 부분 확대 이미지 자동 생성(보조) → 사람 판정 | 검수자·날짜·판정 기록 있음 |
| 19 | 캐릭터 원본·클립 일치 | 자동+사람 | 클립 SHA-256을 `metadata.md` 표와 비교, `.face.json` 체크섬 일치, `tools/face_check.mjs` R1~R4 통과 → 얼굴 외형 변화는 사람이 원본과 나란히 비교 | 체크섬 일치 + 얼굴 검사 통과 + 외형 검수 기록 |
| 20 | 소리 재료 권리 기록 | 자동+사람 | 사용된 모든 음성·BGM 파일에 권리 기록(출처, 라이선스, 상업 이용, 동의서 경로, 확인일)이 있는지 검사 | 빈 항목 0개. 기록 내용의 진위는 **대표 확인** |

## 사람 검수가 꼭 필요한 이유
- 16번: 음정이 "맞다/틀리다"는 보컬 교육 판단이므로 프로그램 측정만으로 확정하지 않는다.
- 18번: 입 모양의 자연스러움은 현재 무료 자동 판정 방법의 신뢰도가 확인되지 않았다 [확인 필요].
- 19번: 체크섬은 "같은 파일인지"만 알려 준다. 립싱크·편집 후 얼굴이 바뀌었는지는 사람이 본다 (CLAUDE.md 4항).
- 20번: 동의서가 실제로 서명됐는지는 프로그램이 알 수 없다.

## 구현 순서
1. 11·12·14·17 (ffmpeg만 사용, 녹음 파일 1개로 바로 시험 가능)
2. 13·15 (spec에 `audio.voice` 항목 추가 후)
3. 19·20 (재료 등록 구조 `assets/` 확정 후, 기존 `face_check.mjs` 재사용)
4. 16 (선생님 시범 녹음 확보 후)
5. 18 (립싱크 시험 승인 후)
